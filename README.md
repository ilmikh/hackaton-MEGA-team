# Велореестр — фронтенд Azik

HTML5, CSS3 и Vanilla JS. Серверная логика и база данных в эту часть не входят.

## Просмотр

```sh
npm start
```

Открыть http://127.0.0.1:3000. Если сервер уже работал до обновления, перезапустить его. Пакеты для просмотра устанавливать не нужно. Можно открыть `frontend/index.html` напрямую.

## Что работает

- Полноэкранные страницы входа и регистрации. Базовая регистрация: фамилия, имя, Telegram username (логин), пароль.
- В деморежиме отправка входа/регистрации переводит в профиль; введённые при регистрации имя и контакт отображаются на главном экране. Это просмотр интерфейса, без проверки пароля и создания аккаунта.
- Из профиля открывается только смена пароля. Изменение логина убрано; настоящий пароль меняется на сервере.
- Переходы между экранами, история браузера, активное меню, окна с Escape/крестиком/закрытием по фону и возвратом фокуса.
- Карточки велосипедов, правильный контекст редактирования Stels/Forward, заявка с выбранным велосипедом.
- Фильтры и подробности собственных заявок; поля места скрываются при освобождении.
- Предпросмотр выбранного фото, проверка формата и 2 МБ для фото велосипеда.
- Выбор свободного места на карте и возврат к форме с сохранением введённых полей в текущей вкладке. У администратора отдельная карта с заполненностью, реестр велосипедов сохранён.

Данные демонстрационные. Ввод теряется после перезагрузки; пароли очищаются при закрытии окна и не записываются в localStorage/sessionStorage. Сохранение профиля, велосипедов и заявок, настоящий вход, QR и ЛКП требуют серверного API. Карта по предоставленной схеме включена: схема/спутник, маркеры, список парковок, свободные места и возврат выбранного места в форму. Места и заполненность демонстрационные. Админу доступны демонстрационный реестр всех велосипедов с поиском и карточками, фильтры заявок и локальные решения. Отклонение требует комментария; решения сбрасываются после перезагрузки и не меняют закрепление места.

## Файлы

- `frontend/index.html` — экраны и формы.
- `frontend/static/veloregistry/app.css` — стили и адаптивность.
- `frontend/static/veloregistry/app.js` — клиентское поведение.
- `frontend/static/veloregistry/parking.js` — карта и выбор места.
- `frontend/static/veloregistry/scanner.js` — камера, снимок и форма загрузки; QR распознаёт бэк.
- `frontend/static/veloregistry/api.js` — необязательная отправка форм в согласованный API; по умолчанию запросов нет.
- `tools/serve.cjs` — только локальная раздача файлов GET/HEAD, без API.
- `tools/check-ui.cjs` — браузерные проверки через Playwright/Edge.

[Подключение форм и карты](docs/FRONTEND_API.md), [QR для бэка](docs/QR_BACKEND.md).

## Проверки

С установленным Playwright: `node tools/check-ui.cjs`. При необходимости `PLAYWRIGHT_MODULE` задаёт путь к модулю. Проверка сама запускает временную статичную раздачу на порту 3013; `UI_URL` позволяет использовать свой адрес.

Проверены переходы, окна, история/фокус, регистрация → профиль, фильтры, фото, мобильный экран, открытие файлом и отсутствие запросов до настройки API. Клиентский JSON-переходник проверен с перехваченными ответами браузера; реального бэка в проверке нет.

Камера открывается на HTTPS/localhost после разрешения браузера. Проверка использует виртуальное видеоустройство Edge: запуск, снимок, остановка, отказ в доступе. Передача `photo` проверяется перехваченным multipart-запросом, без реального API.
