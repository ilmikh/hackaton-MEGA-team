# Велореестр — статичный фронтенд Azik

Интерфейс работает **без бэка и без JavaScript в браузере**. Один HTML-файл содержит экраны; переходы, окна и фильтры заявок сделаны CSS. Node.js только раздаёт файлы.

## Запуск
```
npm start
```
Открыть http://127.0.0.1:3000. Устанавливать npm-пакеты не нужно.
Или открыть frontend/index.html напрямую: интерфейс работает без Node.js и сети.
Для другого порта: переменная окружения PORT.

## Структура
- frontend/index.html — все экраны: профиль, велосипеды, регистрация, QR, мои заявки и административные варианты.
- frontend/static/veloregistry/app.css — общие стили, адаптивность, CSS-переходы и фильтры.
- tools/serve.cjs — локальный HTTP-сервер Node.js, только GET/HEAD; без API, БД и обработки форм.
- docs/design — восемь актуальных визуальных ориентиров, не скриншоты реализации.

Внутри HTML экраны обозначены article id="page-…". Примеры ссылок: #page-profile, #page-bikes, #page-register, #page-requests, #page-admin-scan. Кнопка «Интерфейс администратора» переключает только макет, не выдаёт реальные права.

## Мои заявки
Статичный список с примерами состояний «На рассмотрении», «Одобрена», «Отклонена», CSS-фильтры «Все / На рассмотрении / Завершённые», подробности через details и форма добавления.
Отправка, хранение, отмена и рассмотрение заявок реализуются бэком; в макете эти действия disabled. Данные не отправляются и не сохраняются.
Карта и административная обработка заявок остаются частью тиммейта.

## Подключение
[Инструкция для команды](docs/FRONTEND_API.md), [задачи бэка по QR](docs/QR_BACKEND.md).
От бэка зависит только реальная работа: вход, данные профиля, сохранение велосипеда/заявки, QR и ЛКП. Отображение и переходы доступны сейчас.
Работа — только в azik. .gitignore, временные файлы и старые версии макетов не включены.
