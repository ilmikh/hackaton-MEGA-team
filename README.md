# Велореестр кампуса

Рабочий MVP: FastAPI + SQLite и HTML/CSS/Vanilla JS. Фронт взят из dev, заготовка бэка — из ilya-mikhailov. Работа ведётся в azik. Тимур подтвердил: от ЛКП нужны стили и цвета, интеграция не требуется.

## Запуск Windows / PowerShell
Из корня репозитория, Python 3.12+ и Node.js 18+:
~~~powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m backend.manage seed-parkings
.venv\Scripts\python -m backend.manage create-admin --username campus_admin
npm start
~~~
Открыть http://127.0.0.1:8010. Пароль администратора вводится скрыто в терминале; готового пароля в проекте нет.
Импорт схемы выполняется один раз в пустой БД; повторный запуск не меняет существующие парковки.
Без Node: .venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010.
Linux/macOS: python3 -m venv .venv, далее .venv/bin/python вместо Windows-пути.

npm run preview оставляет автономный просмотр исходного фронта на 3000, без реальных операций. Для рабочего проекта нужен npm start.

## Что работает
Жилец:
- Регистрация, вход/выход, смена пароля; профиль и контакт, логин неизменяем.
- Только свои велосипеды и фото; отдельная карточка; цвет текстом, приметы необязательны.
- Регистрация велосипеда с выбранным свободным местом.
- Заявки: закрепление, перемещение, освобождение, общий фонд, выбытие, передача другому жильцу; отмена до решения.
- QR с фото или снимка камеры; у чужого велосипеда только номер, имя и контакт.
- Печатные заявления/акты, напоминание забрать велосипед к дате выезда.

Админ:
- Полный реестр с поиском, фото, владельцами, местами и статусами.
- Карта с заполненностью, отдельные таблицы свободных/занятых мест.
- Создание парковок, назначение и перемещение места.
- Одобрение/отказ, статусы, выдача велосипеда из общего фонда.
- Жильцы, ручная дата выезда, журнал изменений.
- Полный результат QR и акт списания на разбор.

Права проверяются сервером, а не переключателем макета. До одобрения заявка не бронирует место. Решение и закрепление — одна транзакция с повторной проверкой владельца, статуса и свободности. Повторное решение не повторяет операцию.
Занятость означает закрепление, а не физическое присутствие.
Схема соответствует материалам команды. Ёмкости из старого прототипа необходимо сверить с кампусом; вымышленные занятые велосипеды не импортируются.
Акты — HTML для печати/сохранения PDF, подписи остаются пустыми.

## Данные и конфигурация
Рабочие данные: data/registry.sqlite3 и data/photos, не включаются в коммит.
VELO_DATA_DIR задаёт отдельную папку данных. Для резервной копии остановить сервис и скопировать всю папку.
PORT меняет порт npm start. VELO_PUBLIC_URL задаёт внешний адрес для печатаемых QR; настроить до печати. На телефоне localhost указывает на сам телефон.
За HTTPS-прокси настроить доверенные proxy headers Uvicorn под инфраструктуру кампуса. Cookie: HttpOnly, SameSite, Secure при HTTPS.
ЛКП/SSO не подключены и не требуют паролей или сессий ЛКП. Визуальный ориентир: https://lkp.sirius-campus.ru/login.

## Проверки
~~~powershell
.venv\Scripts\python -m unittest discover -s tests -v
node tools/check-mvp.cjs
~~~
Для браузерной проверки нужны Playwright и Edge; PLAYWRIGHT_MODULE позволяет указать установленный модуль.
check-mvp сам запускает настоящий FastAPI на 8015 с временной БД: аккаунт, фото, выбор места, одобрение, закрепление, генерация PNG и серверное распознавание QR.
tools/check-ui.cjs проверяет сохранённый автономный фронт, не серверные права.
Физическая камера и установка в инфраструктуре кампуса требуют проверки на устройстве.

## Основные файлы
- backend/main.py — API, сессии, заявки, данные, документы, QR.
- backend/manage.py — создание админа и импорт схемы.
- frontend/index.html — сохранённый фронт участников, автономный режим.
- frontend/static/veloregistry/live.js — рабочий интерфейс.
- frontend/static/veloregistry/campus.css — оформление по ЛКП.
- tools/run.cjs — запуск FastAPI из npm.
- docs/BACKEND_EXTRAS.md — документы и напоминания.
- docs/design — восемь визуальных ориентиров.

main/dev не изменяются. Временные архивы, среда Python, данные, пароли и результаты тестов не отправляются в репозиторий.
