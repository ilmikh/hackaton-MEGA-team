# Проверка рабочего MVP

Дата: 8 ноября 2026. Ветка: azik. Основа фронта — dev (fb59512), заготовка API — ilya-mikhailov. По согласованию с Тимуром интеграция с ЛКП не нужна; использованы визуальные ориентиры публичной страницы входа.

| Требование | Реализация |
|---|---|
| Карточка велосипеда | Фото, модель, произвольный цвет, необязательные приметы, владелец, место, отдельная страница |
| Регистрация | Выбор свободного места на карте при заполнении формы, решение администратора |
| Карта | Реальные счётчики закреплённых мест, свободные зелёные, полностью занятые серые; у администратора таблицы свободных и занятых |
| Поиск | Реестр администратора: модель, цвет, место, владелец |
| Приватность | Пользователь видит свои записи; QR чужого велосипеда раскрывает только номер, имя и контакт |
| QR | Генерация и распознавание на сервере, загрузка фото/снимка камеры, закрываемый результат и повторное сканирование |
| Заявки | Регистрация, закрепление, перемещение, освобождение, общий фонд, выбытие, передача жильцу; отмена и решение |
| Документы | Печатные заявления, акты одобренных операций и списания; исторические снимки, пустые поля подписей |
| Администрирование | Реестр, парковки, решения, назначения, фонд, статусы, жильцы, даты выезда, журнал |
| Выезд | Личное напоминание при активном велосипеде и указанной администратором дате; внешняя рассылка не подключена |
| Метка | QR сохраняется после передачи новому владельцу |

## Выполненные проверки

- `python -m unittest discover -s tests -v`: 17/17 успешно.
- `node tools/check-mvp.cjs`: успешно в Edge с отдельной временной БД и настоящим FastAPI. Пройдены регистрация, фото, сохранение формы при переходе на карту, одобрение, закрепление, QR, заявления, дата выезда, напоминание, фонд и назначение владельца. Проверен мобильный размер без горизонтального переполнения и ошибок страницы.
- Негативные сценарии: SQL-инъекции, экранирование HTML, доступ к чужим данным, роли, CSRF, смена пароля и отзыв сессий, неподходящие изображения, ранняя авторизация и ограничения тела загрузки, неверные QR-ссылки, конфликт одновременного закрепления, повторные решения и устаревшие заявки.
- Документы сохраняют исходное содержимое после последующего изменения профиля и описания велосипеда. Повторное списание не переписывает снимок.
- Независимое ревью безопасности: обнаруженные ошибки исправлены и повторно проверены. Это проверка MVP, а не аудит публичной инфраструктуры.

## Перед использованием в кампусе

Нужно сверить ёмкости десяти импортируемых парковок с реальными местами, создать администратора через CLI, настроить HTTPS и внешний адрес QR до печати. Физическая камера телефона и развёртывание в инфраструктуре кампуса ещё не проверены. Занятость показывает закрепление в реестре, а не датчик физического присутствия.

Результаты браузерных проверок и тестовые базы остаются локально в test-results; рабочие данные, пароли, виртуальная среда и временные архивы в коммит не включаются.
