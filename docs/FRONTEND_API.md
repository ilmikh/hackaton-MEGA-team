# Подключение статичного HTML/CSS к FastAPI

## Текущая граница
Azik поставляет только разметку и стили. JavaScript, fetch, события интеграции, локальное хранение и демоадаптер удалены. Старые инструкции про api.js, scanner.js, VELO_CONFIG и события velo:* больше не применяются.

Макеты открываются без API. Ссылки — обычные относительные href, поля — нативный HTML. Кнопки сохранения disabled и type=button: отправка данных сейчас не выполняется.

## Подключение на бэке
1. Раздавать frontend/static как статические файлы; при переносе страниц в шаблоны заменить относительный href CSS на URL приложения.
2. Перенести нужные HTML в шаблоны Jinja2 либо согласовать отдельное подключение интерфейса. Заполнить данные из сессии вместо вымышленных примеров.
3. Заменить статичные ссылки карточек маршрутами реальных велосипедов; список формировать циклом по собственным велосипедам.
4. Добавить form action, method и нужный enctype. Для регистрации нужен multipart/form-data. Кнопки после подключения заменить на type=submit и убрать disabled.
5. Реализовать валидацию, ошибки полей, сообщение об успехе, редирект и проверку прав на сервере.
6. Для административных страниц проверять роль до выдачи HTML. Жилец не должен получать полный реестр или данные комнаты.
7. Комната в admin-owner.html заполняется из ЛКП бэком; до импорта выводится «Нет данных из ЛКП».
8. Авторизация, сессии, CSRF, доступ к фото, хранение файлов и БД — ответственность бэка.

Обычный браузер не отправляет PATCH из HTML-формы. При варианте без JS реализовать POST-обработчики форм; точные URL согласует бэк. Никаких фиксированных рабочих endpoint эта поставка не навязывает.

## Поля
Профиль: display_name, contact_type (telegram/phone), contact_value.
Регистрация: photo (JPEG/PNG/WebP до 2 МБ), model (до 120), color (свободный текст до 80), special_marks (необязательно, до 500), target_spot_id (добавляется после подключения карты).
Описание: model, color, special_marks.
Владельца и роль брать из сессии, не доверять hidden-полю.

Регистрация должна включать выбранное свободное место. Карта/выбор — часть второго фронтенд-разработчика; сейчас ссылка ведёт на явно обозначенную страницу подключения. Backend перепроверяет свободность, создаёт заявку, а подтверждение регистрации и закрепление места выполняет одной транзакцией. До подтверждения место не занято.

## Переходы к части тиммейта
map.html / admin-map.html — карта и административные списки.
requests.html / admin-requests.html — заявки.
Эти файлы пока содержат заглушку, не реализацию чужой части. Заменить href на реальные маршруты команды.
«Добавить заявку» в карточке сейчас ведёт к разделу заявок. Бэк/тиммейт добавляет идентификатор выбранного велосипеда в маршрут или контекст формы.
В регистрационной форме место остаётся невыбранным до подключения карты. Возврат с карты должен сохранять остальные данные; при чистом серверном рендеринге это нужно реализовать бэком. Файл нельзя автоматически восстанавливать в input после перезагрузки.

## QR
См. QR_BACKEND.md. В HTML есть выбор файла, поле capture для снимка на поддерживающих мобильных браузерах и CSS-пример ответа. Это не работающий сканер.
Поле capture — лишь подсказка браузеру; на компьютере может открыться обычный выбор файла. Потоковая камера без JS не реализована.

## Проверка
Проверяются структура HTML, локальные ссылки/якоря, отсутствие JS и внешний вид страниц в браузере. Старые тесты JS-приложения удалены, потому что проверяли удалённую реализацию.
Ни сохранение, ни авторизация, ни реальный API/QR/ЛКП этой поставкой не проверены.
