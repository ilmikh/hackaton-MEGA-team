# Подключение статичного фронтенда к FastAPI

## Сейчас
В frontend один index.html и общий CSS. Нет browser JS, fetch, API-адаптера, localStorage и серверной бизнес-логики.
Node.js (npm start) — только файловый сервер для просмотра. Сайт также открывается напрямую как файл. FastAPI для просмотра не нужен.
Переходы между article.view выполняются якорями #page-… и CSS :target / :has. Требуется современный браузер с :has.
Результаты QR открываются CSS-окном; фильтры заявок работают radio+CSS, подробности — нативным details.

## Экран заявки
#page-requests — список с примерами; #requests-new — форма.
Поля: request_type (place/move/release), bike_id, spot_code (сейчас readonly, заменяется выбором карты), comment (необязательно, до 500).
Реальную заявку создавать нельзя, пока не подключён бэк; кнопки отправки и отмены disabled. В браузере нет записи или изменения статусов.
Список собственных заявок формируется бэком. Владелец — из сессии, не из формы. Одобрение и закрепление — транзакция; свободность места перепроверяется.
По уточнению пользователя статичный экран «Мои заявки» входит в эту часть. Карта и административное рассмотрение — часть тиммейта.

## Другие поля
Профиль: display_name, contact_type, contact_value.
Регистрация: photo (JPEG/PNG/WebP до 2 МБ), model (120), color (свободный текст 80), special_marks (необязательно, 500), target_spot_id после подключения карты.
Редактирование описания: model, color, special_marks.
Ни один макет не сохраняет введённые данные; после перезагрузки они теряются.

## Что подключает бэк
1. Перенести общий HTML в шаблон, вместо статичных примеров подставить данные сессии/БД; для раздачи стилей использовать URL приложения.
2. Добавить form action/method, CSRF, валидацию и ошибки; включить submit только после реализации обработчиков. Регистрация с файлом использует multipart/form-data. HTML-формы поддерживают POST, не PATCH.
3. Скрывать недоступные роли на сервере. Сейчас административные примеры находятся в общем исходнике, потому что они вымышленные. Реальные данные реестра и комнаты нельзя вставлять в HTML жильца и прятать CSS.
4. Проверять принадлежность велосипедов и заявок, права на фото, статус регистрации и доступность места.
5. Связать карту тиммейта с формой регистрации и заявки, передавать выбранный ID места.
6. Реализовать вход, хранение фото, QR и импорт комнаты ЛКП.
Прямые якорные ссылки — для навигации макета, не endpoint и не авторизация.

## Проверки
Проверяются отсутствие скриптов, уникальность ID/якорей, переходы, CSS-фильтры, подробности и окна, отсутствие сетевых запросов API, мобильное отображение и локальная раздача Node.js.
Бэк, реальный вход, сохранение, камера/распознавание QR и ЛКП этой поставкой не реализованы.
