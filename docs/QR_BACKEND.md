# Фото QR — контракт интеграции

Фронтенд открывает getUserMedia по кнопке, захватывает JPEG из video в canvas, показывает предпросмотр и кладёт File в поле `photo`. Фото штатной камерой телефона и загрузка файла работают через ту же форму. QR на клиенте не распознаётся.

`qr-scan` / `admin-qr-scan` подключаются через Veloregistry.connectForm с `encoding: 'form-data'` и согласованным URL. До подключения API отправка отключена. Передаётся один `photo`, без camera_photo. onSuccess отображает согласованный серверный ответ.

Сервер отвечает за распознавание, проверку ссылки/токена и прав, ограниченную карточку жильца / полную администратора, поиск парковки, ошибки и постоянные QR. «Мой QR» пока остаётся местом для изображения сервера, скачивание отключено.

Камера доступна на HTTPS/localhost после разрешения пользователя. При запрете/отсутствии устройства показывается подсказка загрузить файл. Поток закрывается при снимке, уходе со страницы, скрытии вкладки и закрытии. На клиенте JPEG/PNG/WebP до 20 МБ; сервер обязан проверять файл самостоятельно.

В тестах используется виртуальная камера Edge и перехват multipart-запроса. Это не подтверждает работу физической камеры и настоящего серверного распознавания.
